= 仮想マシンが起動しない問題の解決

== シナリオ

ユーザーが仮想マシンを起動しようとしましたが、プロセスが正常に実行されませんでした。

NOTE: このシナリオの主な目的は、障害の原因を調査し、`exercise1` 仮想マシンを `Running` 状態に戻すための是正措置を講じることです。このラボでは、仮想マシンに利用可能なメモリ容量は 8GB です。

exercise1 を修正する手順は以下のとおりです。

=== コンソール

1. 割り当てられたユーザーアカウントを使用して OpenShift コンソールにログインします。

----

----

----

----

[start=2]
2. [Virtualization] - [Virtual Machines] に移動し、VM の状態を確認します。

</a>
++++

[start=3]
3. 仮想マシンがエラー `ErrorUnschedulable` で失敗していることを確認します。


++++
<a href="_images/exercise1/02-step3.png" target="_blank" class="popup">
++++

[start=4]
4. `YAML` タブを開き、仮想マシンの状態を確認してください。以下のエラーメッセージが表示され、失敗しています。

[source]
----
message: '0/6 nodes are available: 3 Insufficient memory, 3 node(s) had untolerated taint {node-role.kubernetes.io/master: }. preemption: 0/6 nodes are available: 3 No preemption victims found for incoming pod, 3 Preemption is not helpful for scheduling.'

[start=5]
5. `spec.domain.memory.guest` フィールドで仮想マシンに割り当てられたメモリを確認します。

          guest: 128Gi
----

6. `yaml` ファイルを編集し、割り当て値を 8Gi に変更します。

[source, yaml]
----

          guest: 8Gi
----

[start=7]

=== コマンドライン (CLI)

1. ログインしていない場合は、割り当てられたユーザーアカウントを使用して `oc` コマンドで OpenShift サーバー API にログインします。

.OpenShift login コマンド
[source,sh,role=execute,subs="attributes"]
----
{login_command}
----

[start=2]
2. 割り当てられたネームスペース {user} に移動します。

[source,sh,role=execute,subs="attributes"]
----
oc project namespace-{user}
----

[start=3]
3. この名前空間で仮想マシンが実行されているかどうか、またその状態を確認してください。出力は以下のようになるはずです。

[source,sh,role=execute,subs="attributes"]
----

NAME                                   AGE   STATUS               READY

----

[start=4]
4. エラーの詳細を確認するために、仮想マシンの状態を確認してください。

[source,sh,role=execute,subs="attributes"]
----
oc describe vm exercise1
----

----
status:

    Message:               Guest VM is not reported as running

    Type:                  Ready
    Last Probe Time:       <nil>

[start=5]
5. 仮想マシンを検査し、`spec.domain.memory.guest` フィールドで仮想マシンに割り当てられているメモリを確認します。

[source,sh,role=execute,subs="attributes"]
----
oc get vm exercise1 -oyaml
----

[source, yaml]
----
        memory:
          guest: 128Gi
----


[start=6]
6. 仮想マシンを編集して、8Giのメモリを割り当てます。

[source,sh,role=execute,subs="attributes"]
----
oc edit vm exercise1
----

[source, yaml]
----
        memory:
          guest: 8Gi
----

[start=7]
7. 仮想マシンを再起動します

[source,sh,role=execute,subs="attributes"]
----

----

[start=8]
8. 仮想マシンが起動するまで待ち、`running` 状態になっていることを確認します

----

----

----

pod/virt-launcher-exercise1         1/1     Running   0          55s

NAME                                   AGE   STATUS    READY
virtualmachine.kubevirt.io/exercise1   96m   Running   True
----

=== 学習内容

この演習では、OpenShift Virtualization 上で動作する仮想マシンは、Pod と同様の動作をすることを学びました。

具体的には、CPU やメモリのリソース要求を設定する際、単一ノードで利用可能なリソースよりも多くのリソースを仮想マシンに割り当てることはできません。
