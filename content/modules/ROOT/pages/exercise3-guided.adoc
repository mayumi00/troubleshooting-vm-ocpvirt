= アプリケーションが外部からアクセスできない問題を修正する

== シナリオ

このアプリケーションは仮想マシン `exercise3` 上で動作し、link:https://exercise3-namespace-{user}.{openshift_cluster_ingress_domain}[https://exercise3-namespace-{user}.{openshift_cluster_ingress_domain}^] を介して外部からアクセスできるように設計されているが、現在接続の問題が発生している。

++++
<a href="_image::exercise3/03-step2.png" target="_blank" class="popup">
++++
image::exercise3/03-step2.png[]
++++
</a>
++++

NOTE: このシナリオにおける主な目的は、OpenShiftクラスタ内のアプリケーションへのアクセスに関わるOpenShiftネットワークコンポーネントを調査することで、問題の原因を究明することです。

演習3の修正手順は以下のとおりです。

=== コンソール

1. 割り当てられたユーザーアカウントを使用してOpenShiftコンソールにログインします。

link:{openshift_console_url}[{openshift_console_url}^]

.ユーザー
[source,sh,role=execute,subs="attributes"]
----
{user}
----

.パスワード
[source,sh,role=execute,subs="attributes"]
----
{password}
----

[start=2]
2. [Virtualization] - [VirtualMachines] に移動し、割り当てられたユーザーアカウントのプロジェクトを選択します。`exercise3` という名前の仮想マシンを探してください。

++++

++++
image::exercise3/01-step2.png[]
++++
</a>
++++

[start=3]
3. 左側のメニューから「Networking」を選択し、この仮想マシンに関連付けられているRouteを探してください。Route名は `exercise3` です。

++++

[start=4]
4. 新しいブラウザタブでRouteにアクセスし、アプリケーションが利用可能かどうかを確認してください。アプリケーションは現在、このエンドポイントでリクエストを処理していません。起動していないか、起動中である可能性があります。

[start=5]
5. Services メニューに移動して、`exercise3` サービスの詳細を取得します。IP アドレスとターゲット ポートを探し、80 に設定されていることを確認します。

++++

</a>

[start=6]
6. [Workloads] に移動し、ポッドを探します。`curlimage` という名前のポッドを選択し、そのターミナルにアクセスします。

[start=7]
7. ポッドからサービスのIPアドレスとポート（80）に対して `curl` コマンドを実行してみてください。

[source,sh,role=execute,subs="attributes"]

NOTE: `IPアドレス`は手順5で確認したものに置き換えてください。
----
curl 172.31.155.175:80
----

[start=8]
8. サービスには「`Hello from exercise3`, you are doing a great job!」というメッセージが表示されるはずです。

[start=9]
9. 次に、routeのターゲットポートを確認します。ネットワーク、routeの順に移動して、`exercise3` ルートのポートが8080に設定されていることを確認します。

++++

[start=10]
10. `yaml` 内のルートを編集し、ターゲットポートを 80 に更新します。

[source, yaml]
----
  to:
    kind: Service
    name: exercise3
    weight: 100
  port:
    targetPort: 80
----

[start=11]
11. 再度route URLにアクセスすると、アプリケーションにアクセスできるようになります。

.演習を検証するには、gradeコマンドを実行してください。
[source,sh,role=execute,subs="attributes"]
----
lab grade exercise3
----

=== Command line (CLI)

1. ログインしていない場合は、割り当てられたユーザーアカウントを使用して　`oc`　コマンドでOpenshiftサーバーAPIにログインします。

.OpenShiftログインコマンド
[source,sh,role=execute,subs="attributes"]
----
{login_command}
----

[start=2]
2. 割り当てられた名前空間 namespace-{user} に移動してください。

[source,sh,role=execute,subs="attributes"]
----
oc project namespace-{user}
----

[start=3]
3.  仮想マシンポッドのIPアドレスを取得します

[source,sh,role=execute,subs="attributes"]
----
PODIP=$(oc get pods -l kubevirt.io/domain=exercise3 \
-o jsonpath="{.items[*].status.podIP}" -n namespace-{user})
----

[start=4]
4. curlimageポッドを使用して仮想マシンをテストし、期待どおりに動作していることを確認してください。

[source,sh,role=execute,subs="attributes"]
----
oc exec curlimage -- curl -s $PODIP
----

[source]
----
Hello from exercise3, you are doing a great job!
----

[start=5]
5. exercise3のサービス詳細を確認し、IPアドレスとポート番号の詳細を取得します。

[source,sh,role=execute,subs="attributes"]
----
SVCIP=$(oc get svc exercise3 \
-o jsonpath="{.spec.clusterIP}" -n namespace-{user})
----

[start=6]
6. curlimageポッド内のサービスからIPアドレスとポート番号をcurlで取得します。

[source,sh,role=execute,subs="attributes"]
----
oc exec curlimage -- curl -s $SVCIP
----

[source]
----
Hello from exercise3, you are doing a great job!
----

[start=7]
7. routeにアクセスしてみて、機能していないことを確認してください。

[source,sh,role=execute,subs="attributes"]
----
oc exec curlimage -- \
curl -s https://exercise3-namespace-{user}.{openshift_cluster_ingress_domain}
----

[start=8]
8. 
routeを確認し、`Endpoint Port` (8080) が間違っています、というエラーがないか確認してください。

[source,sh,role=execute,subs="attributes"]
----
oc describe route exercise3
----

[start=9]
9. route exercise3を編集し、`targetPort` を8080から80に変更します。

[source,sh,role=execute,subs="attributes"]
----
oc edit route exercise3
----

[start=10]
10. または、このパッチを使用します。

[source,sh,role=execute,subs="attributes"]
----
oc patch route exercise3 -p '{"spec":{"port":{"targetPort":80}}}'
----

[start=11]
11. アプリケーションをテストします。

NOTE: アプリケーションは link:https://exercise3-namespace-{user}.{openshift_cluster_ingress_domain}[https://exercise3-namespace-{user}.{openshift_cluster_ingress_domain}^] で利用可能です。

または 

[source,role=execute,subs="attributes"]
----
oc exec curlimage -- curl -s \
https://exercise3-namespace-{user}.{openshift_cluster_ingress_domain}
----

=== 学習内容

この演習では、OpenShift の関連するネットワークコンポーネントをすべて調査することで、アプリケーションへの外部アクセスを妨げる問題のトラブルシューティング方法を学びました。

仮想マシン内でアプリケーションをテストし、サービスを検証し、ルーティングを確認しました。

これらの手順は、問題が OpenShift 内部にあるのか、外部システムにあるのかを判断するのに役立ちます。
