= 仮想マシンが起動しない場合の対処法

== シナリオ

ユーザーが仮想マシンをデプロイして実行しようとしたところ、問題が発生しました。

NOTE: このシナリオの主な目的は、障害の原因を調査し、仮想マシン `exercise2` を `Running` 状態に戻すための是正措置を講じることです。


演習2の修正手順は以下のとおりです。

=== コンソール

1. 割り当てられたユーザーアカウントを使用してOpenShiftコンソールにログインします。

link:{openshift_console_url}[{openshift_console_url}^]

.ユーザー名
[source,sh,role=execute,subs="attributes"]
----
{user}
----

.パスワード
[source,sh,role=execute,subs="attributes"]
----
{password}
----

[start=2]
2. Virtualization - Virtual Machines に移動し、VMの状態を確認します。


++++
<a href="_images/exercise2/01-step2.png" target="_blank" class="popup">
++++
image::exercise2/01-step2.png[]
++++
</a>
++++

[start=3]
3. 仮想マシンがエラー `ErrorUnschedulable` で失敗していることを確認してください。

++++
<a href="_images/exercise2/02-step3.png" target="_blank" class="popup">
++++
image::exercise2/02-step3.png[]
++++
</a>
++++

[start=4]
4.  `YAML` タブに移動し、仮想マシンの状態を確認してください。エラーメッセージが表示されて失敗しています。

[source]
----
message: '0/6 nodes are available: 3 node(s) didn''t match Pod''s node affinity/selector, 3 node(s) had untolerated taint {node-role.kubernetes.io/master: }. preemption: 0/6 nodes are available: 6 Preemption is not helpful for scheduling.'
----

[start=5]
5. この仮想マシンに割り当てられている `NodeSelector` と `Tolerations` を確認します。

[source, yaml]
----
    nodeSelector:
      node-role.kubernetes.io/baremetal: ''
    tolerations:
      - effect: NoSchedule
        key: bare_metal
        value: 'true'
----

[start=6]
6. これらの `NodeSelectors` と `Tolerations` は、クラスタ内のノードと一致しないノードを参照しています。これらを削除してください。

[start=7]
7. 変更を適用するために仮想マシンを再起動してください。


[start=8]
8. 仮想マシンが起動するまで待ち、仮想マシンが` Running` 状態になっていることを確認してください。

++++
<a href="_images/exercise2/03-step8.png" target="_blank" class="popup">
++++
image::exercise2/03-step8.png[]
++++
</a>
++++

演習を検証するには、`grade` コマンドを実行してください。
[source,sh,role=execute,subs="attributes"]
----
lab grade exercise2
----

=== コマンドラインインターフェース (CLI)

1. ログインしていない場合は、割り当てられたユーザーアカウントを使用して `oc` コマンドで OpenShift サーバー API にログインしてください。

OpenShift ログインコマンド
[source,sh,role=execute,subs="attributes"]
----
{login_command}
----

[start=2]
2. 割り当てられたネームスペース {user} に移動してください。

[source,sh,role=execute,subs="attributes"]
----
oc project namespace-{user}
----

[start=3]
3. このネームスペースで仮想マシンが実行されていること、およびそのステータスを確認してください。出力は以下のようになるはずです。

[source,sh,role=execute,subs="attributes"]
----
oc get pod,vm
----

----
NAME                                READY   STATUS    RESTARTS   AGE
pod/virt-launcher-exercise2         0/1     Pending   0          19s

NAME                                   AGE   STATUS               READY
virtualmachine.kubevirt.io/exercise2   20s   ErrorUnschedulable   False
----

[start=4]
4. 仮想マシンの状態を確認して、エラーの詳細を取得します。

[source,sh,role=execute,subs="attributes"]
----
oc describe vm exercise2
----

----
Status:
  Conditions:
    Last Probe Time:       2024-11-26T16:38:19Z
    Last Transition Time:  2024-11-26T16:38:19Z
    Message:               Guest VM is not reported as running
    Reason:                GuestNotRunning
    Status:                False
    Type:                  Ready
    Last Probe Time:       <nil>
    Last Transition Time:  <nil>
    Message:               Not all of the VMI's DVs are ready
    Reason:                NotAllDVsReady
    Status:                False
    Type:                  DataVolumesReady
    Last Probe Time:       <nil>
    Last Transition Time:  2024-11-26T16:38:19Z
    Message:               0/6 nodes are available: 3 node(s) didn't match Pod's node affinity/selector, 3 node(s) had untolerated taint {node-role.kubernetes.io/master: }. preemption: 0/6 nodes are available: 6 Preemption is not helpful for scheduling.
    Reason:                Unschedulable
    Status:                False
    Type:                  PodScheduled
  Created:                 true
  Desired Generation:      1
  Observed Generation:     1
  Printable Status:        ErrorUnschedulable
  Run Strategy:            Always
----

[start=5]
5. 仮想マシンを検査し、この仮想マシンに割り当てられている `NodeSelector` と `Tolerations` を確認します。

[source,sh,role=execute,subs="attributes"]
----
oc get vm exercise2 -oyaml
----

[source, yaml]
----
    nodeSelector:
      node-role.kubernetes.io/baremetal: ''
    tolerations:
      - effect: NoSchedule
        key: bare_metal
        value: 'true'
----

[start=6]
6. これらの `NodeSelectors` と `Tolerations` は、クラスタ内のノードと一致しないノードを参照しています。仮想マシンの設定ファイルを編集して、これらを削除してください。

[source,sh,role=execute,subs="attributes"]
----
oc edit vm exercise2
----

[start=7]
7. 仮想マシンを再起動します。

[source,sh,role=execute,subs="attributes"]
----
virtctl restart exercise2
----

[start=8]
8. 仮想マシンが起動するまで待ち、`running` 状態になっていることを確認してください。

[source,sh,role=execute,subs="attributes"]
----
oc get pod,vm
----

----
NAME                                READY   STATUS    RESTARTS   AGE
pod/virt-launcher-exercise2         1/1     Running   0          40s

NAME                                   AGE    STATUS    READY
virtualmachine.kubevirt.io/exercise2   5m9s   Running   True
----

=== 学習内容

この演習では、`nodeSelector` が定義されていて、その `nodeSelector` で指定されたラベルに一致するノードが存在しない場合、仮想マシンを起動できないことを学びました。
