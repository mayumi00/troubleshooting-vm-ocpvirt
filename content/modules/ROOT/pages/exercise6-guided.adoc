NOTE: 主な目的は、ライブマイグレーションの失敗原因を調査し、是正措置を講じて仮想マシン `exercise6` を別のノードへ正常に移行することです。あなたの任務は、根本原因を特定し、問題を解決することです。

** Podのログを確認してください。この問題は、仮想マシンのディスクが読み取り専用に設定されているため、移行が妨げられていることが原因で発生します。

[source]
----
{"component":"virt-launcher","level":"error","msg":"Operation not supported: Cannot migrate empty or read-only disk vdb","pos":"qemuMigrationDstStartNBDServer:628","subcomponent":"libvirt","thread":"33","timestamp":"2024-11-20T11:44:26.459000Z"}

[start=6]
6. 仮想マシンの設定を編集するには、仮想マシンを停止してください。

[start=7]
7. 仮想マシンを編集し、VM ディスクから `readonly: true` フィールドを削除します。`YAML` セクションに移動し、`spec.template.spec.domain.devices.disks.readonly` フィールドを false に変更します。

[source, yaml]
----
        devices:
          disks:
            - disk:
                bus: virtio
              name: rootdisk
            - disk:
                bus: virtio
                readonly: false
              name: cloudinitdisk
          interfaces:
----

=== コマンドラインインターフェース (CLI)

1. ログインしていない場合は、割り当てられたユーザーアカウントを使用して `oc` コマンドで OpenShift サーバー API にログインします。

.OpenShift login コマンド
[source,sh,role=execute,subs="attributes"]
----
{login_command}
----

[start=2]
2. 割り当てられた namespace-{user} に移動します。

[source,sh,role=execute,subs="attributes"]
----
oc project namespace-{user}
----

[start=3]
3. このネームスペースで仮想マシンが実行されていることを確認してください。出力は次のようになるはずです。

[source,sh,role=execute,subs="attributes"]

----

----

exercise6   11m   Running   10.132.2.11   worker-cluster-1   True
----

[start=4]
4. `virtctl`コマンドを使用して仮想マシンを移行します。

[source,sh,role=execute,subs="attributes"]

5. VirtualMachine Instant Migration`オブジェクトを取得して、移行ステータスを確認してください。出力結果には、移行が`失敗`フェーズにあることが示されるはずです。

[source,sh,role=execute,subs="attributes"]

----

----

[start=6]
6. 仮想マシンを停止します。

[source,sh,role=execute,subs="attributes"]
----

----

[start=7]
7. 仮想マシンを編集し、VM ディスクから `readonly: true` フィールドを削除します。`spec.template.spec.domain.devices.disks.readonly` フィールドを false に変更します。

[source,sh,role=execute,subs="attributes"]
----

----


[source, yaml]
----
        devices:
          disks:
            - disk:
                bus: virtio
              name: rootdisk
            - disk:
                bus: virtio
                readonly: false
              name: cloudinitdisk
          interfaces:
----

[start=8]
8. 仮想マシンを再起動してください。

[source,sh,role=execute,subs="attributes"]

----

[start=9]
9. 仮想マシンが配置されているノードを確認してください。

[source,sh,role=execute,subs="attributes"]

oc get vmi
----

----
NAME        AGE   PHASE     IP            NODENAME                 READY
exercise6   98s   Running   10.132.2.11   worker-cluster-vmnjk-1   True
----

10. 仮想マシンを移行します。

[source,sh,role=execute,subs="attributes"]

11. `VirtualMachine Instant Migration`オブジェクトを取得して、移行ステータスを確認してください。出力結果には、移行が`Succeeded`フェーズにあることが示されるはずです。

=== 学習内容

この演習では、OpenShift Virtualization において、読み取り専用ディスクが接続された仮想マシンはノード間でライブマイグレーションできないことを学びました。

この制限は、ライブマイグレーションではターゲットノード上に仮想マシンの新しいインスタンスを作成する必要があるため、RWO ディスクの単一ノードアクセス制限によって失敗します。
