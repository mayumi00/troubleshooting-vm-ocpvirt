= 仮想マシンで追加ディスクにアクセスできない

== シナリオ

ユーザーから、`exercise5` 仮想マシンに追加したディスクが、`fdisk` コマンドまたは `lsblk` コマンドを実行してもリストに表示されないという報告がありました。ユーザーは、`exercise5-vol-data1` という名前のディスクを作成し、それを `exercise5` という名前の仮想マシンにマウントしたいと考えています。

NOTE: ユーザーが `lsblk` コマンドまたは `fdisk` コマンドを実行した際に `exercise5-vol-data1` ディスクが表示されるように、問題のトラブルシューティングと解決を行ってください。

演習5を修正する手順は以下のとおりです。

=== コマンドラインインターフェース (CLI)

1. ログインしていない場合は、割り当てられたユーザーアカウントを使用して `oc` コマンドで OpenShift サーバー API にログインします。

.OpenShift ログインコマンド
[source,sh,role=execute,subs="attributes"]
----
{login_command}
----

[start=2]
2. 指定されたネームスペース namespace-{user} に移動します。

[source,sh,role=execute,subs="attributes"]
----
oc project namespace-{user}
----

[start=3]
3. 仮想マシンの一覧を表示する。


[source,sh,role=execute,subs="attributes"]
----
oc get virtualmachine
----

[start=4]
5. 追加データディスク `exercise5-vol-data1` のデータボリュームが空であることを確認してください。

[source,sh,role=execute,subs="attributes"]
----
oc get datavolume
----

[start=5]
4. 追加データディスク `exercise5-vol-data1` に `PersistentVolumeClaims` が関連付けられていないことを確認してください。

[source,sh,role=execute,subs="attributes"]
----
oc get pvc
----

[start=6]
6. `exercise5-vol-data1` データボリュームの設定を確認し、defaultStorageClass の設定が誤っていないか確認してください。

[source,sh,role=execute,subs="attributes"]
----
oc get datavolume exercise5-vol-data1 -n namespace-{user} -o yaml
----

[start=7]
7. データボリューム exercise5-vol-data1 を削除します。

[source,sh,role=execute,subs="attributes"]
----
oc delete datavolume exercise5-vol-data1
----

[start=8]
8. `ocs-storagecluster-ceph-rbd` の `storageClassName` を使用して、名前を `exercise5-vol-data1`、サイズを30GiBとして、DataVolumeを再度作成します。

[source,sh,role=execute]
----
oc create -f - <<EOF
apiVersion: cdi.kubevirt.io/v1beta1
kind: DataVolume
metadata:
  name: exercise5-vol-data1
spec:
  preallocation: false
  source:
    blank: {}
  storage:
    resources:
      requests:
        storage: 30Gi
    storageClassName: ocs-storagecluster-ceph-rbd
EOF
----

[start=9]
9. exercise5-vol-data1の状態を確認し、追加ディスクのプロビジョニングが完了するまでお待ちください。

[source,sh,role=execute,subs="attributes"]
----
watch oc get pvc
----

[start=10]
10. `exercise5` の仮想マシンコンソールに移動し、ラボユーザーの認証情報を使用してログインしてください。

[source,sh,role=execute,subs="attributes"]
----
virtctl console exercise5
----

[start=11]
11. `lsblk` または `fdisk -l` コマンドを使用してディスクの可用性を確認してください。`exercise5-vol-data1` から追加された新しいディスクが存在し、ユーザーがフォーマットしてマウントできる状態になっているはずです。

=== 学習内容

この演習では、永続ボリューム要求 (PVC) が作成されるまで、ディスクは仮想マシンに提示されないことを学びました。

OpenShift Virtualization でデータボリュームの `storageClassName` を変更するには、既存のデータボリュームを削除し、目的のストレージクラスで新しいデータボリュームを作成する必要があります。
