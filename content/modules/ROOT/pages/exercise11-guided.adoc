=== コマンドライン (CLI)

1. ログインしていない場合は、割り当てられたユーザーアカウントを使用して `oc` コマンドで OpenShift サーバー API にログインします。

.OpenShift login コマンド
[source,sh,role=execute,subs="attributes"]
----
{login_command}
----

[start=2]
2. 割り当てられたネームスペース {user} に移動します。

[source,sh,role=execute,subs="attributes"]
----
oc project namespace-{user}
----

[start=3]
3. 仮想マシンの一覧を表示します。

[source,sh,role=execute,subs="attributes"]
----
oc get virtualmachine
----

[start=4]
4. 通信が機能していないことを確認します。

[source,sh,role=execute,subs="attributes"]
----
virtctl ssh lab-user@exercise11-a \
-c 'ping -c 3 192.168.0.11'
----

[start=5]
5. 仮想マシン `exercise11-a` と `exercise11-b` に IP アドレスが設定されていることを確認します。

[source,sh,role=execute,subs="attributes"]
----
virtctl ssh lab-user@exercise11-a \
-c 'ip -4 addr show dev eth1'
----

[source,sh,role=execute,subs="attributes"]
----
virtctl ssh lab-user@exercise11-b \
-c 'ip -4 addr show dev eth1'
----

[start=6]
6. cloud-init を使用した CRD VirtualMachine 上で、仮想マシンに静的 IP アドレスが設定されていることを確認します。

[source,sh,role=execute,subs="attributes"]
----
oc get vmi exercise11-a -n namespace-{user} \
-o jsonpath='{.spec.volumes[?(@.cloudInitNoCloud)].cloudInitNoCloud.networkData}'
----

[source,sh,role=execute,subs="attributes"]
----
oc get vmi exercise11-b -n namespace-{user} \
-o jsonpath='{.spec.volumes[?(@.cloudInitNoCloud)].cloudInitNoCloud.networkData}'
----

[start=7]
7. 問題は、仮想マシン `exercise11-b` にあります。この仮想マシンは /32 サブネットマスクで誤って設定されていますが、正しくは /24 サブネットマスクを使用する必要があります。 IPアドレスはcloud-initで設定されているため、設定を修正するには仮想マシンを再作成する必要があります。

仮想マシンを再作成する前に、以下のコマンドを使用して `exercise11-b` を保存し、不要なフィールドを削除してください。

[source,sh,role=execute,subs="attributes"]
----
oc get virtualmachine exercise11-b -o yaml |\ sed -e '/managedFields:/,/^[^ ]/d' \
-e '/creationTimestamp:/d' -e '/resourceVersion:/d' \
-e '/uid:/d' -e '/status:/,/^[^ ]/d' > exercise11-b.yaml
----

[start=9]
9. YAMLファイル内のIPアドレスを編集し、/32から/24に変更してください。

[source,sh,role=execute,subs="attributes"]
----
vim exercise11-b.yaml
----

[start=10]
10. exercise11-b 仮想マシンを削除します

[source,sh,role=execute,subs="attributes"]
----
oc delete virtualmachine exercise11-b
----

[start=11]
11. 編集した YAML ファイルを適用します

[source,sh,role=execute,subs="attributes"]
----
oc apply -f exercise11-b.yaml
----

[start=12]
12. 通信が正常に動作していることを確認します

[source,sh,role=execute,subs="attributes"]
----
virtctl ssh lab-user@exercise11-a \
-c 'ping -c 3 192.168.0.11'
----

=== 学習内容

この演習では、VirtualMachine マニフェストで定義されている cloud-init の設定を変更するには、仮想マシンを再作成する必要があることを学びました。

これは、cloud-init が仮想マシンの初回起動時にのみ実行されるためです。
