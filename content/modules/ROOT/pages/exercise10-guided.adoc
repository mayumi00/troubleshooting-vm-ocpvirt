=== コマンドライン (CLI)

1. ログインしていない場合は、割り当てられたユーザーアカウントを使用して`oc`コマンドでOpenShiftサーバーAPIにログインします。

.OpenShift login command
[source,sh,role=execute,subs="attributes"]
----
{login_command}
----

[start=2]
2. 割り当てられたネームスペース{user}に移動します。

[source,sh,role=execute,subs="attributes"]
----
oc project namespace-{user}
----

[start=3]
3. 仮想マシンの一覧を表示します。

[source,sh,role=execute,subs="attributes"]
----
oc get virtualmachine
----

[start=4]
4. 仮想マシンが異なるノードで実行されていることを確認します。

[source,sh,role=execute,subs="attributes"]
----
oc get pods -o wide
----

[start=5]
5. 通信が機能していないことを確認します。

[source,sh,role=execute,subs="attributes"]
----
virtctl ssh lab-user@exercise10-a \
-c 'ping -c 5 192.168.0.11'
----

[start=6]
6. 仮想マシン a と b で使用されているセカンダリ ネットワークを取得します。

[source,sh,role=execute,subs="attributes"]
----
oc get vmi exercise10-a -n namespace-{user} \
-o jsonpath='{.spec.networks[?(@.multus)].multus.networkName}'
----

[source,sh,role=execute,subs="attributes"]
----
oc get vmi exercise10-b -n namespace-{user} \
-o jsonpath='{.spec.networks[?(@.multus)].multus.networkName}'
----

[start=7]
7. セカンダリネットワークのYAMLを取得します

[source,sh,role=execute,subs="attributes"]
----
oc get network-attachment-definitions.k8s.cni.cncf.io exercise10-nad -o yaml
----

[start=8]
8. NaD (NetworkAttachmentDefinition) が正しく設定されていることを確認します`br-{user}` インターフェースを使用しています。この `Linux bridge` が物理ポートに接続されていないことを確認してください (1 つ以上の veth* ポートが使用されています)。

つまり、仮想マシンは同じノードで実行されている場合にのみ通信できます。

したがって、`Linux bridge` の代わりに `layer2` ネットワークを使用するように NaD を再作成する必要があります。`layer2-nad.yaml` を作成して適用してください。

[source,sh,role=execute,subs="attributes"]
----
oc get nns -o yaml | grep -A 2 -B 73 br-{user} | grep -A4 port
----

[source,sh,role=execute,subs="attributes"]
----
vim layer2-nad.yaml
----

[source,sh,role=execute,subs="attributes"]
----
apiVersion: k8s.cni.cncf.io/v1
kind: NetworkAttachmentDefinition
metadata:
name: exercise10-nad-layer2
namespace: namespace-{user}
spec:

config: '{"name":"exercise10-nad-layer2","type":"ovn-k8s-cni-overlay","cniVersion":"0.3.1","topology":"layer2","netAttachDefName":"namespace-{user}/exercise10-nad-layer2"}'
----

[source,sh,role=execute,subs="attributes"]
----
oc apply -f layer2-nad.yaml
----

[start=9]
9. 仮想マシン `exercise10-a` と `exercise10-b` をシャットダウンします。

[source,sh,role=execute,subs="attributes"]
----
virtctl stop exercise10-a
virtctl stop exercise10-b
----

[start=10]
10. 仮想マシンのセカンダリネットワークを変更します。

[source,sh,role=execute,subs="attributes"]
----
oc patch vm exercise10-a -n namespace-{user} --type='json' \
-p='[{"op": "replace", "path": "/spec/template/spec/networks/1/multus/networkName", "value": "exercise10-nad-layer2"}]'
----

[source,sh,role=execute,subs="attributes"]
----
oc patch vm exercise10-b -n namespace-{user} --type='json' \
-p='[{"op": "replace", "path": "/spec/template/spec/networks/1/multus/networkName", "value": "exercise10-nad-layer2"}]'
----

[start=11]
11. 仮想マシンを起動します。

[source,sh,role=execute,subs="attributes"]
----
virtctl start exercise10-a
virtctl start exercise10-b
----

[start=12]
12. 仮想マシンが起動したら、しばらく待ってから通信を再度確認してください。

[source,sh,role=execute,subs="attributes"]
----
virtctl ssh lab-user@exercise10-a \
-c 'ping -c 3 192.168.0.11'
----

=== 学習内容

この演習では、仮想マシン間の通信を有効にするには、Linux Bridgeではなく、OVN `layer2` を使用したセカンダリネットワークを設定する必要があることを学びました。

OVNの `localnet` および `Linux Bridge` オプションは、 `NodeNetworkConfigurationPolicy` が定義されていないため、使用できません。これは、ブリッジに物理ポートが接続されていないことを意味します。
