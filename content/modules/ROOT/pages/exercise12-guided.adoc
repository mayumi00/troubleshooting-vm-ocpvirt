=== コマンドライン (CLI)

1. ログインしていない場合は、割り当てられたユーザーアカウントを使用して `oc` コマンドで OpenShift サーバー API にログインします。

.OpenShift login コマンド
[source,sh,role=execute,subs="attributes"]
----
{login_command}
----

[start=2]
2. 割り当てられたネームスペース {user} に移動します。

[source,sh,role=execute,subs="attributes"]
----
oc project namespace-{user}
----

[start=3]
3. 仮想マシンの一覧を表示します。

[source,sh,role=execute,subs="attributes"]
----
oc get virtualmachine
----

[start=4]
4. exercise12-a の IP アドレスを取得します。

[source,sh,role=execute,subs="attributes"]
----
oc get vmi exercise12-a -n namespace-{user} \
-o jsonpath='{.status.interfaces[1].ipAddress}'
----

[start=5]
5. exercise12-b の IP アドレスを取得します

[source,sh,role=execute,subs="attributes"]
----
oc get vmi exercise12-b -n namespace-{user} \
-o jsonpath='{.status.interfaces[1].ipAddress}'
----

[start=6]
6. 仮想マシン exercise12-b 上で実行されているアプリケーションに IP アドレスを使用してアクセスし、動作しないことを確認します。


NOTE:  手順5で定義した値にIPアドレスを変更することを忘れないでください。

[source,sh,role=execute,subs="attributes"]
----
virtctl ssh lab-user@exercise12-a \
-c 'curl --silent --connect-timeout 3 http://IP'
----

[source,subs="attributes"]
----
Warning: Permanently added 'vmi/exercise12-a.namespace-{user}' (ED25519) to the list of known hosts.
exit status 28
----

[start=7]
7. プロジェクト namespace-{user} に 2 つの multi-networkpolicies が設定されていることを確認します。

[source,sh,role=execute,subs="attributes"]
----
oc get multi-networkpolicies.k8s.cni.cncf.io
----

[start=8]
8. マルチネットワークポリシー `deny-by-default` が namespace-{user} 上のすべての接続をブロックしていることを確認します。

[source,sh,role=execute,subs="attributes"]
----
oc get multi-networkpolicies.k8s.cni.cncf.io \
deny-by-default -o yaml
----

[source,subs="attributes"]
----
apiVersion: k8s.cni.cncf.io/v1beta1
kind: MultiNetworkPolicy
metadata:
  name: deny-by-default
  namespace: namespace-{user}
spec:
  ingress: []
  podSelector: {}
  policyTypes:
  - Ingress
----

[start=9]
9. マルチネットワークポリシー `allow-80-on-exercise12` が、`exercise12-b` 仮想マシンからのすべての接続のみを許可していることを確認します。

[source,sh,role=execute,subs="attributes"]
----
oc get multi-networkpolicies.k8s.cni.cncf.io \
allow-80-on-exercise12 -o yaml
----
[source,subs="attributes"]
----
apiVersion: k8s.cni.cncf.io/v1beta1
kind: MultiNetworkPolicy
metadata:
  name: allow-80-on-exercise12
  namespace: namespace-{user}
spec:
  ingress:
  - from:
    - podSelector:
        matchLabels:
          vm.kubevirt.io/name: exercise12-b
    ports:
    - port: 80
      protocol: TCP
  podSelector:
    matchLabels:
      app: exercise12
  policyTypes:
  - Ingress
----

[start=10]
10. このネットワークポリシーでは、`podSelector` で使用されているラベルにエラーがあります。正しいラベルは `vm.kubevirt.io/name: exercise12-a` で​​す。

[source,subs="attributes"]
----
apiVersion: k8s.cni.cncf.io/v1beta1
kind: MultiNetworkPolicy
metadata:
  name: allow-80-on-exercise12
  namespace: namespace-{user}
spec:
  ingress:
  - from:
    - podSelector:
        matchLabels:
          vm.kubevirt.io/name: exercise12-b   <--
    ports:
    - port: 80
      protocol: TCP
  podSelector:
    matchLabels:
      app: exercise12
  policyTypes:
  - Ingress
----

[start=11]
11. 仮想マシン exercise12-a が接続元になるように、multi-networkpolicy を編集し、ラベルの内容を `exercise12-a` に変更してください。


[source,sh,role=execute,subs="attributes"]
----
oc edit multi-networkpolicies.k8s.cni.cncf.io \
allow-80-on-exercise12
----

[start=12]
12. 仮想マシン exercise12-b 上で実行されているアプリケーションに IP アドレスを使用してアクセスし、正常に動作することを確認してください。


NOTE: 手順5で定義した値にIPアドレスを変更することを忘れないでください。

[source,sh,role=execute,subs="attributes"]
----
virtctl ssh lab-user@exercise12-a \
-c 'curl --silent --connect-timeout 3 http://IP'
----

[source,subs="attributes"]
----
Warning: Permanently added 'vmi/exercise12-a.namespace-{user}' (ED25519) to the list of known hosts.
Hey Hey Hey, it's working!!

=== 学習内容

この演習では、`MultiNetworkPolicy` カスタムリソース定義を使用して、セカンダリネットワークに接続された2台の仮想マシン間の通信を制限する方法を学びました。
