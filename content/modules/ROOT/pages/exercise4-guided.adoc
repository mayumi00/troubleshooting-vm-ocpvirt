= パフォーマンスが低下した仮想マシン

== シナリオ

このシナリオでは、`exercise4` という名前の仮想マシンが現在 `running` 状態です。開発チームから、この仮想マシン上で稼働しているアプリケーションのパフォーマンス問題が発生しているとの報告がありました。

あなたのタスクは、CPU、メモリ、その他の関連メトリックを含む仮想マシンのリソース使用状況を分析することで、この問題を調査することです。問題解決のために必要に応じて仮想マシンのコンピューティングリソースを調整することは許可されていますが、再起動は許可されていません。

[NOTE]
====
* 目標は、仮想化インフラストラクチャ内でボトルネックや設定ミスを特定し、アプリケーションの効率を向上させるための最適化を実施することです。
* 仮想マシン内で実行中のプロセスを強制終了しないでください。
* 仮想マシンを再起動しないでください。
* このラボで使用する仮想マシンに割り当てられるCPUは4です。
====

演習4を修正する手順は以下のとおりです。

=== コマンドラインインターフェース (CLI)

1. ログインしていない場合は、割り当てられたユーザーアカウントを使用して `oc` コマンドで OpenShift サーバー API にログインします。

.OpenShift ログインコマンド
[source,sh,role=execute,subs="attributes"]
----
{login_command}
----

[start=2]
2. 指定されたネームスペース namespace-{user} に移動します。

[source,sh,role=execute,subs="attributes"]
----
oc project namespace-{user}
----

[start=3]
3. 仮想マシンの一覧を表示します。

[source,sh,role=execute,subs="attributes"]
----
oc get virtualmachine
----

[source,subs="attributes"]
----
NAME        AGE     STATUS    READY
exercise4   3m29s   Running   True
----

[start=4]
4. ポッドをリスト表示します。

[source,sh,role=execute,subs="attributes"]
----
oc get pods
----

[source,subs="attributes"]
----
NAME                            READY   STATUS    RESTARTS   AGE
virt-launcher-exercise4-lb66m   1/1     Running   0          3m41
----

[start=5]
5. CPUの数を確認します。

[source,sh,role=execute,subs="attributes"]
----
oc get vm exercise4 -n namespace-{user} \
-o jsonpath='{.spec.template.spec.domain.cpu}'
----

[source,subs="attributes"]
----
{"cores":1,"sockets":2,"threads":1}
----

[start=6]
6. OS仮想マシン内でこの情報を検証します。

[source,sh,role=execute,subs="attributes"]
----
virtctl ssh lab-user@exercise4 -c 'lscpu | grep Socket'
----

[source,subs="attributes"]
----
Warning: Permanently added 'vmi/exercise4.namespace-{user}' (ED25519) to the list of known hosts.
2
----

[start=7]
7. 仮想マシンがCPUをほぼ100%使用していることを確認してください。

[source,sh,role=execute,subs="attributes"]
----
oc adm top pods
----

[source,subs="attributes"]
----
NAME                            CPU(cores)   MEMORY(bytes)   
virt-launcher-exercise4-lb66m   1993m        1224Mi
----

[start=8]
8. 仮想マシンのソケット数を2から4に変更します。

[source,sh,role=execute,subs="attributes"]
----
oc patch vm exercise4 -n namespace-{user} --type='json' \
-p='[{"op": "replace", "path": "/spec/template/spec/domain/cpu/sockets", "value": 4}]'
----

[start=9]
9. 仮想マシンが4つのソケットで実行されていることを確認します。

[source,sh,role=execute,subs="attributes"]
----
oc get vm exercise4 -n namespace-{user} \
-o jsonpath='{.spec.template.spec.domain.cpu}'
----

[source,subs="attributes"]
----
{"cores":1,"sockets":4,"threads":1}
----

[start=10]
10. OS仮想マシン内でこの情報を検証します。

[source,sh,role=execute,subs="attributes"]
----
virtctl ssh lab-user@exercise4 -c 'lscpu | grep Socket'
----

[source,subs="attributes"]
----
Warning: Permanently added 'vmi/exercise4.namespace-{user}' (ED25519) to the list of known hosts.
4
----

[start=11]
11. 仮想マシンのCPU使用率を確認するコマンドです。

[source,sh,role=execute,subs="attributes"]
----
virtctl ssh lab-user@exercise4 \
--command "top -b -n 1 | grep 'Cpu(s)' | awk '{print \$2 \"% Used\"}'"
----

=== 学習内容

この演習では、RHEL 9 仮想マシンを操作する際に、CPU 構成を変更するために仮想マシンをシャットダウンまたは再起動する必要がないことを学びました。

代わりに、仮想マシンが実行中の状態で CPU ホットプラグ操作を実行できます。

この演習では使用していませんが、仮想マシンを再起動せずにメモリのホットプラグを実行することも可能です。
